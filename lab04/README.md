#### Число −99

Отрицательные целые числа хранятся в дополнительном коде: берём двоичную запись модуля, инвертируем все биты и прибавляем 1 ([Дополнительный код (Википедия)](https://ru.wikipedia.org/wiki/Дополнительный_код)).

99 = 64 + 32 + 2 + 1 = `0110 0011`

1 байт:

```
 99      = 0110 0011
инверсия = 1001 1100
+1       = 1001 1101   
```

Для 2 и 4 байт делается то же самое, только слева больше разрядов. У положительного 99 они нулевые, после инверсии становятся единицами. Поэтому длинная запись отрицательного числа — это короткая, дополненная слева единицами:

```
1 байт:  1001 1101                                        
2 байта: 1111 1111 1001 1101                              
4 байта: 1111 1111 1111 1111 1111 1111 1001 1101          
```


#### Наибольшее и наименьшее число в int

```
наибольшее:  2147483647 = 0111 1111 1111 1111 1111 1111 1111 1111 = 0x7FFFFFFF
наименьшее: -2147483648 = 1000 0000 0000 0000 0000 0000 0000 0000 = 0x80000000
```

#### Символ `#`

Код символа `#` в таблице ASCII — 35 = 32 + 2 + 1:

```
'#' = 35 = 0010 0011
```

Файл [02/main.cpp](02/main.cpp). Функция `show` печатает запись литерала, его значение и тип через `typeid`. В g++ сокращения такие: `i` — `int`, `j` — `unsigned int`, `l` — `long`, `m` — `unsigned long`, `x` — `long long`, `y` — `unsigned long long`, `c` — `char`.


* **Системы счисления.** Десятичная — без префикса. Восьмеричная — начинается с `0` (`052` — это 42, а не 52). Шестнадцатеричная — `0x` или `0X`, цифры `A–F` в любом регистре. Двоичная — `0b` или `0B` (с C++14).
* **Разделитель разрядов** `'` (с C++14) — только для удобства чтения, на значение не влияет: `1'000'000`, `0b1010'1010`.
* **Суффиксы.** `u`/`U` — беззнаковый. `l`/`L` — `long`. `ll`/`LL` — `long long`. Их можно сочетать в любом порядке (`ul`, `LU`, `ULL`, `LLU`) и с любой системой счисления. Регистр не важен, но `ll` должно быть одного регистра — `lL` нельзя.
* **Тип литерала без суффикса** выбирается по значению: берётся первый тип, в который число помещается. Для десятичных литералов это `int` → `long` → `long long`, поэтому `2147483648` (на 1 больше `INT_MAX`) сразу получил тип `long long`: на Windows `long` тоже 32-битный. Для шестнадцатеричных, восьмеричных и двоичных в список добавляются беззнаковые типы: `int` → `unsigned int` → `long` → … Поэтому `0x80000000` и `0xFFFFFFFF` — `unsigned int`, а `0x100000000` — уже `long long`.
* **Отрицательных литералов нет.** `-42` — это унарный минус перед литералом `42`. `-42u` — минус перед беззнаковым числом, результат тоже беззнаковый: 2³² − 42 = 4294967254.
* `'A'` — символьный литерал, тип `char`, но по сути это тоже целое число 65.

### Задание 3

```cpp
char a = 'a';
a = a + 10;
std::cout << a;
a = a + 250;
std::cout << a;
```

Переменная типа `char` хранит не букву, а её код по таблице ASCII. При выводе `cout` превращает код обратно в букву.

Нужная часть таблицы ASCII:

| код | символ | | код | символ |
|---|---|---|---|---|
| 97 | a | | 104 | h |
| 98 | b | | 105 | i |
| 99 | c | | 106 | j |
| 100 | d | | 107 | k |
| 101 | e | | 108 | l |
| 102 | f | | 109 | m |
| 103 | g | | 110 | n |

`char` занимает 1 байт, то есть 8 бит, и в нём помещается 256 разных значений. Если результат больше, лишние старшие биты отбрасываются, а значит, из числа вычитается 256.

Работа программы по строкам:

| строка | что считается | результат | помещается в 1 байт? | в `a` | вывод |
|---|---|---|---|---|---|
| `char a = 'a';` | код `'a'` | 97 | да | 97 = `'a'` | |
| `a = a + 10;` | 97 + 10 | 107 | да | 107 = `'k'` | |
| `std::cout << a;` | | | | | `k` |
| `a = a + 250;` | 107 + 250 | 357 | нет | 357 − 256 = 101 = `'e'` | |
| `std::cout << a;` | | | | | `e` |

Сложение `a + 10` и `a + 250` выполняется в типе `int`: перед арифметикой `char` повышается до `int`. Поэтому 357 сначала честно получается, а обрезается только при записи обратно в `a`.

Почему 357 превратилось в 101, видно по двоичной записи. 357 = 256 + 64 + 32 + 4 + 1:

| вес разряда | 256 | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
|---|---|---|---|---|---|---|---|---|---|
| 357 | 1 | 0 | 1 | 1 | 0 | 0 | 1 | 0 | 1 |
| в `char` (8 бит) | — | 0 | 1 | 1 | 0 | 0 | 1 | 0 | 1 |

Разряд 256 — девятый, в 1 байт он не помещается и пропадает. Остаётся 64 + 32 + 4 + 1 = 101, а это код буквы `e`.

Итог вывода: `ke`.

### Задание 4

Файл [04/main.py](04/main.py):

```python
a = 'a'
a = chr(ord(a) + 10)
print(a, end='')
a = chr(ord(a) + 250)
print(a)
print(ord('a'), ord('a') + 10, ord('k') + 250, hex(ord(a)))
```

Вывод:

```
kť
97 107 357 0x165
```

Первая буква та же — `k`, а вместо `e` получилась `ť` (латинская t с гачеком, U+0165).

`ord` возвращает код символа, `chr` — символ по коду. Арифметику над символами в Python напрямую делать нельзя (`'a' + 10` — ошибка), поэтому код достают через `ord`, складывают как обычные числа и превращают обратно через `chr`.

Вывод отличается потому, что в Python нет 1-байтового `char`. Строка состоит из символов Unicode, а `chr` принимает любой код от 0 до 0x10FFFF ([документация Python: chr](https://docs.python.org/3/library/functions.html#chr)). Целые числа в Python вообще не переполняются. Значит, 357 остаётся 357, и `chr(357)` выдаёт символ Unicode с этим номером. В C++ то же 357 обрезалось до 8 бит и превратилось в 101.

### Задание 5

Файл [05/main.cpp](05/main.cpp). Я добавил промежуточный вывод `y` и `z`:

```
y = 14464, z = 14464
40000 7232
```

`unsigned short` — 2 байта, диапазон 0…65535 (2¹⁶ = 65536). Перед арифметикой `unsigned short` повышается до `int`, вычисление идёт без переполнения, а обрезка по модулю 65536 происходит только при присваивании обратно в `unsigned short`.

**y = x + x, затем y − x:**

```
x + x      = 40000 + 40000 = 80000          (int)
y          = 80000 mod 65536 = 80000 - 65536 = 14464
y - x      = 14464 - 40000 = -25536         (int)
y          = -25536 mod 65536 = -25536 + 65536 = 40000
```

**z = x · 2, затем z / 2:**

```
x * 2      = 80000                          (int)
z          = 80000 mod 65536 = 14464
z / 2      = 14464 / 2 = 7232
z          = 7232
```

Почему одно работает, а другое нет. Сложение и вычитание по модулю 2¹⁶ согласованы: если обе операции сделаны по модулю, ответ правильный по модулю. Получилось (2x − 65536) − x = x − 65536, а при приведении к `unsigned short` лишние −65536 снова исчезают. Ошибка от переполнения при сложении компенсировалась при вычитании.

С делением так не выходит. Деление не совместимо с остатком по модулю: (2x − 65536) / 2 = x − 32768. Потерянные 65536 при делении на 2 превратились в 32768, а это уже не кратно 65536, и обратно не вернётся: 40000 − 32768 = 7232. Информация о старшем бите потерялась при первом присваивании в `z`, и деление её не восстанавливает.

### Задание 6

Файл [06/main.cpp](06/main.cpp). Сначала считаю вручную, 2³² = 4294967296.

1. `2000000000 + 1000000000` — оба литерала `int` (помещаются, максимум 2147483647). Сумма 3000000000 в `int` не помещается — переполнение знакового целого, по стандарту это неопределённое поведение. Фактически берутся младшие 32 бита в дополнительном коде: 3000000000 − 4294967296 = **−1294967296**. g++ при компиляции предупреждает: `integer overflow in expression of type 'int' results in '-1294967296'`.
2. `2000000000U + 1000000000U` — оба `unsigned int`, максимум 4294967295. 3000000000 помещается: **3000000000**.
3. `2500000000U + 2500000000U` — `unsigned int`, сумма 5000000000 не помещается. Для беззнаковых переполнение определено — результат по модулю 2³²: 5000000000 − 4294967296 = **705032704**.
4. `2500000000LL + 2500000000LL` — `long long`, 64 бита, всё помещается: **5000000000**.
5. `20000U * 200000U` = 4000000000 ≤ 4294967295, помещается: **4000000000**.
6. `200000U * 200000U` = 40000000000. 40000000000 / 4294967296 ≈ 9.31, значит вычитаем 9 · 4294967296 = 38654705664: 40000000000 − 38654705664 = **1345294336**.

### Задание 7

Файл [07/main.py](07/main.py):

```python
x = int(input())
y = (x << 9) + (x << 8) + (x << 7) + (x << 6) + (x << 5) + (x << 3)
print(y)
```

Сдвиг влево на k — это умножение на 2ᵏ. Поэтому 1000 раскладываем на степени двойки по двоичной записи:

```
1000 = 512 + 256 + 128 + 64 + 32 + 8 = 2⁹ + 2⁸ + 2⁷ + 2⁶ + 2⁵ + 2³
```

x · 1000 = x·2⁹ + x·2⁸ + x·2⁷ + x·2⁶ + x·2⁵ + x·2³ — сумма шести сдвигов. Вычитание использовать нельзя, поэтому короткий вариант `(x << 10) - (x << 4) - (x << 3)` не подходит.

Проверка:

```
7      -> 7000
123    -> 123000
-5     -> -5000
0      -> 0
```

С отрицательными тоже работает: в Python `<<` для отрицательных чисел тоже умножает на 2ᵏ.

### Задание 8

Записываю нужные числа в двоичном виде:

```
1000 = 512+256+128+64+32+8   = 11 1110 1000
 500 = 256+128+64+32+16+4    = 01 1111 0100
 100 = 64+32+4               = 00 0110 0100
1234 = 1024+128+64+16+2      = 100 1101 0010
```

**`(1000 & 100) << 10`**

```
1000 = 11 1110 1000
 100 = 00 0110 0100
   &   00 0110 0000 = 64 + 32 = 96
```

`96 << 10` = 96 · 2¹⁰ = 96 · 1024 = **98304**

**`(1000 >> 4) & 15`**

```
1000      = 11 1110 1000
1000 >> 4 =      11 1110 = 62     (младшие 4 бита ушли, то же что 1000 // 16)
15        =      00 1111
&         =      00 1110 = 14
```

Ответ **14**. `& 15` оставляет 4 младших бита, то есть по сути это биты 4…7 исходного числа.

**`~1234 + 1234`**

`~` инвертирует все биты. В дополнительном коде −n = ~n + 1, отсюда ~n = −n − 1. Значит, ~1234 = −1235, и −1235 + 1234 = **−1**.

То же без формулы: n и ~n не имеют общих единиц, а вместе дают все единицы. Их сумма — число из одних единиц, а в дополнительном коде это −1.

**`(1000 ^ 500) & 63`**

```
1000 = 11 1110 1000
 500 = 01 1111 0100
   ^   10 0001 1100 = 512 + 16 + 8 + 4 = 540
  63 = 00 0011 1111
   &   00 0001 1100 = 16 + 8 + 4 = 28
```

Ответ **28**.

**`(100 << 3) + (100 >> 3)`**

```
100 << 3 = 100 · 8 = 800
100 >> 3 = 100 // 8 = 12       (0110 0100 -> 0000 1100)
800 + 12 = 812
```

Ответ **812**.
