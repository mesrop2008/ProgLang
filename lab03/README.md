### Задание 1

**Тип** — это множество значений, которые может принимать переменная или выражение, вместе с набором операций над этими значениями. Тип определяет, сколько памяти занимает значение и как интерпретируются биты. Например, `int` — целые числа с операциями `+ - * / %`, `bool` — `true`/`false` с логическими операциями.

**Статическая типизация** — тип каждой переменной и выражения известен на этапе компиляции и после объявления не меняется. Ошибки несоответствия типов находит компилятор ещё до запуска программы. Примеры: C++, Java.

**Динамическая типизация** — тип привязан не к переменной, а к значению и выясняется во время выполнения. Одна и та же переменная может сначала хранить число, потом строку. Ошибка типов обнаруживается только когда до неё дойдёт выполнение. Пример: Python.

**Неявная типизация** — тип переменной не пишется программистом, а выводится транслятором из инициализирующего выражения. Например, `auto x = 3.5;` в C++ или `var s = "abc";` в Java. Типизация при этом может оставаться статической — тип просто вычисляется компилятором.

**Явное преобразование типа** — преобразование, которое программист записывает в коде сам: `(int)3.7`, `static_cast<double>(n)`, `int("12")` в Python.

**Неявное преобразование типа** — преобразование, которое транслятор выполняет автоматически, без записи в коде, по правилам языка. Например, в `1 + 2.5` целое `1` превращается в `double`.

**Сильная (строгая) типизация** — язык не смешивает значения разных типов в выражениях и допускает только безопасные неявные преобразования (без потери информации). Всё остальное требует явного преобразования, иначе ошибка. Пример: Java, Python.

**Слабая типизация** — язык сам выполняет много неявных преобразований, в том числе с возможной потерей данных или между «несвязанными» типами (число ↔ логическое значение, `double` → `int`). Программа транслируется, но результат может оказаться неожиданным. Пример: C, C++, JavaScript.

Источники: [Типизация данных (Википедия)](https://ru.wikipedia.org/wiki/Типизация_данных), [Сильная и слабая типизация (Википедия)](https://ru.wikipedia.org/wiki/Сильная_и_слабая_типизация).

### Задание 2

Правила по [cppreference: Implicit conversions](https://en.cppreference.com/w/cpp/language/implicit_conversion) и [Arithmetic operators — usual arithmetic conversions](https://en.cppreference.com/w/cpp/language/operator_arithmetic#Conversions).

#### Преобразования при присваивании

Значение справа приводится к типу переменной слева.

* Целое → целое более широкого типа (`int` → `long long`) — значение не меняется.
* Целое → беззнаковое (`unsigned`) — берётся остаток от деления на 2ⁿ, где n — число бит. Поэтому `unsigned int u = -1;` даёт 4294967295.
* Целое → знаковое более узкого типа, если значение не помещается — до C++20 результат зависел от реализации, с C++20 тоже берётся по модулю 2ⁿ (лишние старшие биты отбрасываются).
* Вещественное → целое — дробная часть отбрасывается (округление к нулю): `int i = 3.7;` даёт 3, `-3.7` даёт −3. Если целая часть не помещается в тип — неопределённое поведение.
* Целое → вещественное — значение сохраняется, но для больших чисел может потеряться точность (у `float` всего 24 бита мантиссы).
* `double` → `float` — округление, возможна потеря точности.
* Любое число или указатель → `bool` — ноль (и `nullptr`) даёт `false`, всё остальное — `true`.
* `bool` → число — `false` даёт 0, `true` даёт 1.

#### Преобразования при арифметических действиях

Перед бинарной операцией (`+ - * / % < > ==` и т.д.) оба операнда приводятся к общему типу («обычные арифметические преобразования»):

1. Если один из операндов `long double` — второй приводится к `long double`.
2. Иначе, если один `double` — второй к `double`.
3. Иначе, если один `float` — второй к `float`.
4. Иначе оба целые. Сначала выполняется **целочисленное повышение**: `bool`, `char`, `short` (и их `unsigned`-варианты, если их значения помещаются в `int`) превращаются в `int`. Поэтому арифметики в типах меньше `int` не бывает.
5. Если после повышения типы одинаковые — всё.
6. Если оба знаковые или оба беззнаковые — меньший по рангу приводится к большему (`int` → `long` → `long long`).
7. Если беззнаковый тип имеет ранг не меньше знакового — знаковый приводится к беззнаковому (`int` и `unsigned int` → `unsigned int`).
8. Если знаковый тип может вместить все значения беззнакового — беззнаковый приводится к знаковому (`unsigned int` и `long long` → `long long`).
9. Иначе оба приводятся к беззнаковой версии знакового типа.

Тип результата — это и есть этот общий тип. Отсюда два важных следствия: деление двух `int` — целочисленное, а смешивание `int` с `unsigned` делает отрицательные числа огромными положительными.

#### Преобразования с логическими значениями

* В условиях (`if`, `while`, `for`, `?:`) и в операндах `!`, `&&`, `||` выражение приводится к `bool`: 0, 0.0 и нулевой указатель → `false`, остальное → `true`. Поэтому пишут `if (n)` и `while (p)`.
* В арифметике и сравнениях `bool` повышается до `int`: `true` → 1, `false` → 0. Поэтому `true + true == 2`, а `x == true` на самом деле сравнивает `x` с 1.
* Операции сравнения и логические операции `!`, `&&`, `||` возвращают `bool`. Побитовые `& | ^` над `bool` сначала повышают операнды до `int`, поэтому возвращают `int`.

Пояснения по строкам:

* `int i = 3.7` — C++ молча отбрасывает дробную часть. Java считает, что это потеря данных, и требует явно написать `(int)3.7`.
* `bool flag = 10`, `int k = true` — в C++ `bool` и числа свободно переводятся друг в друга. В Java `boolean` — отдельный тип, не связанный с числами, преобразования между ними нет вообще, даже явного.
* `if (n)`, `while (n--)` — C++ превращает число в условие по правилу «не ноль — истина». В Java условие обязано быть `boolean`, надо писать `if (n != 0)`.
* `true + true` — в C++ оба `true` повышаются до `int`, получается 2. В Java арифметика над `boolean` не определена.
* `int cut = big` — C++ отбрасывает старшие биты (5000000000 mod 2³² = 705032704), результат неверный, но программа собирается. Java запрещает сужение `long` → `int` без явного приведения.
* `char ch = 'A' + n` — в Java `'A' + n` имеет тип `int`, а сужать `int` в `char` без приведения можно только для константы. В C++ такое сужение делается автоматически.

Вывод: обе программы статически типизированы (типы проверяет компилятор), но C++ допускает много неявных преобразований с потерей информации и смешивает числа с логическими значениями — это слабая типизация. Java разрешает неявно только расширяющие безопасные преобразования, всё остальное — ошибка компиляции, это сильная типизация.

### Задание 7

Файл [07/main.cpp](07/main.cpp). Вывод (g++, Windows):

```
4
7
269058867200000
8000000000000000
sizeof(long) = 4, sizeof(long long) = 8
```

Преобразования выполняются для каждой операции отдельно, по типам её двух операндов, а не для всего выражения сразу. Поэтому от порядка действий зависит, в каком типе считается промежуточный результат.

* `(x / y) / d` — сначала `7 / 4`, оба `int`, деление целочисленное: 1. Потом `1 / 0.25`, `1` приводится к `long double`, получается 4.
* `(x / d) / y` — сначала `7 / 0.25`, `x` приводится к `long double`, получается 28. Потом `28 / 4`, `y` приводится к `long double`, получается 7. Дробная часть нигде не терялась.
* `(a * b) * c` — `a * b` считается в типе `long`, а на Windows `long` 32-битный. 200000 · 200000 = 4·10¹⁰ не помещается в 32 бита — переполнение знакового целого, это неопределённое поведение. Фактически отбросились старшие биты и получилось 1345294336. Только потом это число приводится к `long long` и умножается на `c`: 1345294336 · 200000 = 269058867200000.
* `a * (b * c)` — в `b * c` один операнд `long long`, поэтому `b` сразу приводится к `long long` и произведение 4·10¹⁰ помещается. Затем `a` тоже приводится к `long long`: 8·10¹⁵ — правильный ответ.

На Linux, где `long` 64-битный, обе последние строки дали бы 8000000000000000: переполнения в `a * b` там нет.

### Задание 8

Файл [08/main.cpp](08/main.cpp). Программа перебирает все сочетания из значений 1 и 2 (этого хватает, чтобы получить все варианты равенств), а потом считает выражение для чисел, введённых с клавиатуры:

```
x=1 y=1 z=1   1 + 1 == 1  ->  0
x=1 y=1 z=2   1 + 0 == 1  ->  1
x=1 y=2 z=1   0 + 1 == 1  ->  1
x=1 y=2 z=2   0 + 0 == 1  ->  0
x=2 y=1 z=1   0 + 0 == 1  ->  0
x=2 y=1 z=2   0 + 1 == 1  ->  1
x=2 y=2 z=1   1 + 0 == 1  ->  1
x=2 y=2 z=2   1 + 1 == 1  ->  0
x y z: 5 5 7
true
```

Как считается выражение:

1. `(x == y)` и `(x == z)` — это `bool`.
2. Для `+` оба `bool` повышаются до `int`: сумма 0, 1 или 2.
3. Для `==` правый операнд `true` тоже повышается до `int`, то есть до 1.
4. Итог: выражение истинно, когда сумма равна ровно 1.

Значит, истина получается, когда выполняется **ровно одно** из двух равенств:

* `x == y` и `x != z` (например, 5 5 7);
* `x == z` и `x != y` (например, 5 7 5).

Во всех остальных случаях ложь: и когда все три равны (сумма 2, а не 1), и когда `x` не равен ни `y`, ни `z` (сумма 0). Случай «все равны» интуитивно кажется истинным, но из-за сравнения с 1 он даёт ложь.

### Задание 9

Файлы [09/main.py](09/main.py), [09/main.cpp](09/main.cpp), [09/Main.java](09/Main.java), [09/Fixed.java](09/Fixed.java).

#### Python

```
x=1 y=1 z=1   x==y==z -> True   (x==y)==z -> True
x=2 y=2 z=2   x==y==z -> True   (x==y)==z -> False
x=1 y=2 z=0   x==y==z -> False   (x==y)==z -> True
x=2 y=2 z=1   x==y==z -> False   (x==y)==z -> True
x=0 y=1 z=0   x==y==z -> False   (x==y)==z -> True
```

В Python сравнения образуют цепочку: `x == y == z` означает `x == y and y == z` ([документация Python, Comparisons](https://docs.python.org/3/reference/expressions.html#comparisons)). Результат совпадает с математическим смыслом «все три равны». Для сравнения я добавил столбец со скобками `(x==y)==z` — это уже другое выражение, в нём `bool` сравнивается с числом (`True == 1`, `False == 0`), и получается то же, что в C++.

#### C++

```
x=1 y=1 z=1   x==y==z -> true
x=2 y=2 z=2   x==y==z -> false
x=1 y=2 z=0   x==y==z -> true
x=2 y=2 z=1   x==y==z -> true
x=0 y=1 z=0   x==y==z -> true
```

В C++ цепочек нет. `==` левоассоциативен, поэтому `x == y == z` — это `(x == y) == z`. Сначала получается `bool`, затем он повышается до `int` (0 или 1) и сравнивается с `z`. Поэтому 2 2 2 даёт ложь (1 ≠ 2), а 1 2 0 даёт истину (0 == 0). Выражение фактически проверяет, что `z` равен 1 при равных `x` и `y` или равен 0 при неравных.

#### Java

```
Main.java:4: error: incomparable types: boolean and int
        System.out.println(x == y == z);
                                  ^
1 error
```

Разбор тот же, что в C++: `(x == y) == z`. Но в Java `boolean` не преобразуется в `int`, и сравнивать их нельзя — ошибка компиляции. Чтобы проверить равенство трёх чисел, надо явно писать `x == y && y == z` ([09/Fixed.java](09/Fixed.java)):

```
x=1 y=1 z=1   x==y && y==z -> true
x=2 y=2 z=2   x==y && y==z -> true
x=1 y=2 z=0   x==y && y==z -> false
x=2 y=2 z=1   x==y && y==z -> false
x=0 y=1 z=0   x==y && y==z -> false
```

### Задание 10

Файл [10/main.py](10/main.py). Запуск с пустым вводом:

```
'' -> False
'0' -> True
'False' -> True
' ' -> True
'abc' -> True
name: 
Hello, anonymous
False True True
```

Запуск с вводом `Mesrop`:

```
name: Mesrop
Hello, Mesrop
False True True
```

Когда строка стоит в `if`, `while`, `and`/`or`/`not`, Python неявно вызывает для неё проверку истинности. Для строк правило простое: пустая строка — ложь, любая непустая — истина ([документация Python, Truth Value Testing](https://docs.python.org/3/library/stdtypes.html#truth-value-testing)). Содержимое не важно: `"0"`, `"False"` и даже строка из одного пробела — истина.

На этом основан приём `name or "anonymous"`: если пользователь ничего не ввёл, `name` — пустая строка, то есть ложь, и `or` возвращает значение по умолчанию. `not ""` даёт `True` — ещё один пример того же преобразования.
