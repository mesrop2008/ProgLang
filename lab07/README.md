```cpp
int x=10, y=3;
std::cout << std::min(x=15, x+y);
```
```cpp
int x=10, y=3;
x=15, y+=x, x+=y;
```
```cpp
int x=10, y=9;
if (x>y++ && y++>9)
  cout << "yes" << endl;
cout << y;
```

*Тексты программ разместите в папке с номером задания*

#### Решение

Файлы с программами размещены в папке [01](01): [01/frag1.cpp](01/frag1.cpp), [01/frag2.cpp](01/frag2.cpp), [01/frag3.cpp](01/frag3.cpp).

##### Фрагмент 1

```cpp
int x=10, y=3;
std::cout << std::min(x=15, x+y);
```

Файл: [01/frag1.cpp](01/frag1.cpp).

**Поведение:** данный фрагмент обладает **неоднозначным поведением**.

**Причина:**

1. Функция `std::min` принимает два аргумента: выражение присваивания `x=15` и выражение `x+y`.
2. По правилам языка C++ порядок вычисления аргументов функции не зафиксирован. Компилятор имеет право вычислить первым либо `x=15`, либо `x+y`.
3. Согласно [стандарту ISO/IEC 14882:2014 (C++14), раздел intro.execution](https://timsong-cpp.github.io/cppwp/n4140/intro.execution), вычисления аргументов функции не упорядочены относительно друг друга. Если в одном выражении происходит модификация переменной (`x=15`) и чтение той же переменной (`x+y`) без точек следования между ними, программа приводит к **неопределенному поведению**.
4. Согласно [стандарту ISO/IEC 14882:2017 (C++17), раздел intro.execution](https://timsong-cpp.github.io/cppwp/n4659/intro.execution), вычисления аргументов функции выполняются неделимо друг относительно друга, но порядок между ними всё равно не зафиксирован:
   - Если первым вычисляется `x=15`, то переменная `x` становится равной 15. Затем вычисляется второй аргумент `x+y = 15 + 3 = 18`. Вызов `std::min(15, 18)` возвращает **15**.
   - Если первым вычисляется `x+y`, то считается `10 + 3 = 13`. Затем переменной `x` присваивается 15. Вызов `std::min(15, 13)` возвращает **13**.

При компиляции компилятором `g++` выдается предупреждение:
```
frag1.cpp:5:27: warning: operation on 'x' may be undefined [-Wsequence-point]
    5 |    std::cout << std::min(x=15, x+y);
```
Результат работы программы при запуске в `g++`:
```
13
```

##### Фрагмент 2

```cpp
int x=10, y=3;
x=15, y+=x, x+=y;
```

Файл: [01/frag2.cpp](01/frag2.cpp).

**Поведение:** данный фрагмент обладает **однозначным** поведением.

**Причина:**

В выражении используется оператор «запятая».
По [стандарту ISO/IEC 14882:2017 (C++17), раздел expr.comma](https://timsong-cpp.github.io/cppwp/n4659/expr.comma):
1. Оператор «запятая» имеет наименьший приоритет среди всех операторов языка и вычисляется строго слева направо.
2. Вычисление левого операнда и все его побочные эффекты строго предшествуют вычислению правого операнда. Результат левого выражения отбрасывается.

Пошаговое выполнение:
1. `x = 15`: переменной `x` присваивается значение 15. Результат выражения отбрасывается.
2. `y += x`: вычисляется `y = 3 + 15 = 18`. Переменная `y` получает значение 18.
3. `x += y`: вычисляется `x = 15 + 18 = 33`. Переменная `x` получает значение 33.

Поведение строго детерминировано. Вывод программы:
```
x=33 y=18
```

##### Фрагмент 3

```cpp
int x=10, y=9;
if (x>y++ && y++>9)
  cout << "yes" << endl;
cout << y;
```

Файл: [01/frag3.cpp](01/frag3.cpp).

**Поведение:** данный фрагмент обладает **однозначным** поведением.

**Причина:**

В условии используется логический оператор `&&`.
По [стандарту ISO/IEC 14882:2017 (C++17), раздел expr.log.and](https://timsong-cpp.github.io/cppwp/n4659/expr.log.and):
1. Оператор `&&` вычисляется строго слева направо.
2. Вычисление левого операнда и все связанные с ним изменения строго предшествуют вычислению правого операнда.
3. Оператор `&&` реализует короткое замыкание: правый операнд вычисляется только тогда, когда левый операнд истинен.

Пошаговое выполнение:
1. Вычисляется левый операнд `x > y++`:
   - На входе `x = 10`, `y = 9`.
   - Постфиксный инкремент возвращает значение 9.
   - Сравнение `10 > 9` истинно.
   - Значение `y` увеличивается до 10.
2. Так как левый операнд истинен, вычисляется правый операнд `y++ > 9`:
   - На входе `y = 10`.
   - Постфиксный инкремент возвращает значение 10.
   - Сравнение `10 > 9` истинно.
   - Значение `y` увеличивается до 11.
3. Поскольку оба операнда истинны, условие выполняется и программа печатает `yes`.
4. Следующая строка выводит текущее значение `y`, равное 11.

Вывод программы:
```
yes
11
```

### Задание 2 **(2)**
*Как записать следующие строки программы на С++ в виде одного выражения? Приведите несколько способов, в том числе с использованием операторов инкремента.*
*Проверьте работу написанных программ*
```cpp
x=x+1;
z=z+2*x+3*y;
y=y+1;
```
*Тексты программ разместите в папке с номером задания*

#### Решение

Файл с реализацией и проверкой: [02/main.cpp](02/main.cpp).

Исходные строки:
```cpp
x=x+1;
z=z+2*x+3*y;
y=y+1;
```

При исходных значениях `x=2, y=3, z=0`:
* `x` увеличивается на 1: $x = 3$;
* `z` вычисляется с новым $x$ и старым $y$: $z = 0 + 2 \cdot 3 + 3 \cdot 3 = 15$;
* `y` увеличивается на 1: $y = 4$.
Итоговые значения: `x=3, y=4, z=15`.

##### Способы записи в виде одного выражения

**Способ 1: через оператор «запятая»**
```cpp
x=x+1, z=z+2*x+3*y, y=y+1;
```
Оператор «запятая» гарантирует последовательное вычисление выражений слева направо: сначала изменяется `x`, затем вычисляется `z`, затем изменяется `y`.

**Способ 2: через префиксный инкремент и оператор «запятая»**
```cpp
z += 2*(++x) + 3*y, ++y;
```
Префиксный инкремент `++x` сначала увеличивает `x` на 1, и его новое значение сразу подставляется в `2*(++x)`. Переменная `y` в вычислении `z` используется до инкремента. Затем через запятую выполняется `++y`.

**Способ 3: через префиксные инкременты обеих переменных**
```cpp
++x, z += 2*x + 3*y, ++y;
```
Сначала префиксно увеличивается `x`, затем вычисляется `z`, затем префиксно увеличивается `y`.

**Способ 4: в одно выражение без запятой с префиксным и постфиксным инкрементами**
```cpp
z += 2*(++x) + 3*y++;
```
1. `++x` увеличивает `x` на 1 и возвращает его новое значение, которое умножается на 2.
2. `y++` возвращает старое значение `y`, которое умножается на 3, а затем увеличивает `y` на 1.
3. Результат прибавляется к `z`.

Все три модифицируемые переменные (`x`, `y`, `z`) являются отдельными объектами, поэтому неопределенное поведение отсутствует. Компилятор собирает код без предупреждений.

##### Результат работы программы [02/main.cpp](02/main.cpp)
```
Original: x=3 y=4 z=15
Method 1: x=3 y=4 z=15
Method 2: x=3 y=4 z=15
Method 3: x=3 y=4 z=15
Method 4: x=3 y=4 z=15
```

### Задание 4 **(2)**

*Почему присваивание* ```(++x)=y``` *является синтаксически правильным, а*
```(x++)=y``` - *нет? Запишите текст сообщения об ошибке, переведите и объясните его.*

#### Решение

Файлы с кодом: [04/prefix.cpp](04/prefix.cpp) и [04/postfix.cpp](04/postfix.cpp).

##### Сообщение об ошибке компилятора

При сборке файла [04/postfix.cpp](04/postfix.cpp) компилятор `g++` выдает ошибку:
```
postfix.cpp:4:7: error: lvalue required as left operand of assignment
    4 |     (x++) = y;
      |     ~~^~~
```

**Перевод сообщения:** «В качестве левого операнда присваивания требуется lvalue».

Файл [04/prefix.cpp](04/prefix.cpp) со строкой `(++x) = y;` компилируется без ошибок и выводит `x=10`.

##### Объяснение причины

Причина заключается в категории значений, которые возвращают префиксная и постфиксная формы инкремента по [стандарту C++ (см. cppreference: Категории значений)](https://ru.cppreference.com/w/cpp/language/value_category):

| Оператор | Тип возвращаемого значения | Категория значения | Может стоять слева от `=`? |
|---|---|---|---|
| Префиксный `++x` | `int&` | lvalue | Да |
| Постфиксный `x++` | `int` | prvalue | Нет |

1. **Префиксный инкремент `++x`:**
   Увеличивает значение `x` в памяти и возвращает ссылку на саму переменную `x` (`int&`). Результат является **lvalue** — выражением, обозначающим конкретный объект в памяти. В C++ оператор присваивания требует, чтобы слева находилось модифицируемое lvalue. Поэтому строка `(++x) = y` синтаксически верна: `x` сначала увеличивается, а затем в него записывается значение `y`.

2. **Постфиксный инкремент `x++`:**
   Увеличивает переменную `x`, но возвращает её прежнее значение как временную величину (`int`). Результат является **prvalue** — временным значением, не привязанным к сохраняемому объекту памяти. Присваивание временному значению запрещено, поэтому компилятор отклоняет строку `(x++) = y;`.

### Задание 5 **(2)**

*Программисты на Python для обмена значений двух переменных часто пишут строку*
```python
a,b = b,a
```
*Проверьте, будет ли аналогичная строка на С++ (с точкой с запятой в конце) являться синтаксически
правильной? Будет ли она обменивать значения переменных? Как в языке С++ вычисляется это выражение?*

#### Решение

Файл с кодом: [05/main.cpp](05/main.cpp).

##### Ответы на вопросы

1. Строка `a,b = b,a;` является **синтаксически правильной** в C++ и успешно компилируется.
2. Значения переменных она **не обменивает**, переменные остаются прежними.
3. Выражение вычисляется как цепочка выражений через оператор «запятая»: `(a), (b = b), (a);`.

##### Подробный разбор вычисления

По [стандарту ISO/IEC 14882:2017 (C++17), раздел expr.comma](https://timsong-cpp.github.io/cppwp/n4659/expr.comma) оператор присваивания `=` имеет приоритет выше, чем оператор «запятая» `,`.
Поэтому компилятор разбирает выражение как:
```cpp
(a) , (b = b) , (a);
```

Оператор запятая вычисляет подвыражения слева направо:
1. Вычисляется `a`: значение считывается и отбрасывается.
2. Вычисляется присваивание `b = b`: переменная `b` присваивается сама себе, её значение не изменяется.
3. Вычисляется `a`: значение считывается и отбрасывается.

Переменная `a` вообще не перезаписывается, а `b` присваивается сама себе. Значения не меняются.

### Задание 7 **(2)**

*Как работает следующая программа? Как зависит результат от исходного значения?*
```cpp
int x;
std::cin >> x;
x-->0 && x-->0 && x-->0 && x-->0 && x-->0;
std::cout << x;
```

#### Решение

Файл с кодом: [07/main.cpp](07/main.cpp).

##### Разбор работы программы

1. Выражение `x-->0` разбирается компилятором как:
   ```cpp
   (x--) > 0
   ```
   Постфиксный декремент сначала сравнивает текущее значение `x` с нулем, а затем уменьшает `x` на 1.
2. В выражении записана цепочка из 5 таких условий, соединенных оператором `&&`.
3. По [стандарту ISO/IEC 14882:2017 (C++17), раздел expr.log.and](https://timsong-cpp.github.io/cppwp/n4659/expr.log.and) оператор `&&` реализует короткое замыкание: если очередное условие ложно, дальнейшие проверки не выполняются, и декременты прекращаются.

##### Зависимость результата от исходного значения

1. **Если $x < 0$:**
   Первое условие сразу ложно (`false`). Выполняется ровно один декремент. Вычисление остальных условий отсекается. Результат равен **$x - 1$**.

2. **Если $0 \le x \le 4$:**
   Условия проверяются по очереди, уменьшая `x` на единицу. Процесс останавливается в тот момент, когда значение `x` до декремента станет равным 0. Проверка `0 > 0` дает `false`, `x` уменьшается на 1 до `-1`, и вычисления прекращаются. Поэтому для любого $x$ от 0 до 4 результат **всегда равен `-1`**.

3. **Если $x \ge 5$:**
   Все 5 условий истинны, так как при каждой проверке `x` остается больше нуля. Срабатывают все 5 декрементов. Результат равен **$x - 5$**.

### Задание 8 **(3)**

*Какое число выводит следующий фрагмент программы? Посчитайте результат без использования
вычислительной техники. Отчет должен содержать процесс вычислений.*
```cpp
int s = 0;
for (int i = 0, j = 5;i+j <= 16;(i<j ? i : j)++)
   (s += i) += j;
std::cout << s;
```

#### Решение

Файл с кодом: [08/main.cpp](08/main.cpp).

##### Анализ выражений

1. **Тело цикла: `(s += i) += j;`**
   Сначала вычисляется `s += i`, возвращающее ссылку на `s`. Затем к ней прибавляется `j`. Итого на каждом шаге к `s` прибавляется `i + j`.
2. **Шаг цикла: `(i < j ? i : j)++`**
   Тернарный оператор в C++ возвращает ссылку на `i` (если $i < j$) или на `j` (если $i \ge j$). Выбранная переменная затем увеличивается на 1.

##### Пошаговый процесс вычислений

Начальные значения: `s = 0`, `i = 0`, `j = 5`.

### Задание 9 **(3)**
*Рассмотрите следующую программу. Предполагается, что на вход подается некоторый
индекс в массиве - число от нуля до девяти и значение, которое надо записать по этому индексу.*
```cpp
int i = 0;
std::vector<int> x(10);
std::cin >> i >> x[i];
std::cout << x[i];
```
*Проверьте работу этой программы на различных компиляторах. Найдите два компилятора (можно 
проверить онлайн компиляторы), на которых эта программа будет давать различные ответы при одинаковом
вводе. Как это объяснить?*

#### Решение

Файл с кодом: [09/main.cpp](09/main.cpp).

##### Сравнение результатов на двух компиляторах

Подадим на вход строку `3 42` (индекс 3, значение 42):

| Компилятор | Режим стандарта | Результат вывода | Значения в векторе |
|---|---|---|---|
| **GCC 14.2** | `-std=c++14` | **`42`** | `x[3] = 42` |
| **MSVC 19.x** | `/std:c++14` | **`0`** | `x[0] = 42`, а `x[3] = 0` |

На одинаковых входных данных компиляторы **GCC** и **MSVC в режиме C++14** выдают разные ответы.

##### Объяснение причин

Выражение `std::cin >> i >> x[i];` является вызовом функции:
```cpp
operator>>( operator>>(std::cin, i) , x[i] )
```
Внешняя функция `operator>>` принимает два аргумента:
1. Левый аргумент: `operator>>(std::cin, i)` — поток ввода после чтения `i`.
2. Правый аргумент: `x[i]` — ссылка на элемент вектора.

По [стандарту ISO/IEC 14882:2014 (C++14), раздел intro.execution](https://timsong-cpp.github.io/cppwp/n4140/intro.execution) порядок вычисления аргументов функции не был зафиксирован.

1. **Компилятор MSVC в C++14** вычисляет аргументы функции справа налево:
   - Сначала вычисляется правый аргумент `x[i]`. Так как `i = 0`, вычисляется ссылка на элемент `x[0]`.
   - Затем вычисляется левый аргумент `operator>>(cin, i)`, который считывает из потока значение `3` в переменную `i`.
   - Затем вызывается внешний `operator>>`, который считывает число `42` по ранее полученной ссылке в `x[0]`.
   - В строке `cout << x[i]` выводится элемент `x[3]`. Поскольку в `x[3]` ничего не записывалось, выводится исходный **`0`**.

2. **Компилятор GCC (а также MSVC в стандарте C++17)** вычисляет аргументы слева направо.
В стандарте C++17 было принято [предложение WG21 P0145R3](http://www.open-std.org/jtc1/sc22/wg21/docs/papers/2016/p0145r3.pdf). Согласно [стандарту ISO/IEC 14882:2017 (C++17), раздел expr.shift](https://timsong-cpp.github.io/cppwp/n4659/expr.shift), в выражении `E1 >> E2` вычисление `E1` строго предшествует вычислению `E2`. Поэтому `cin >> i` гарантированно выполняется до вычисления `x[i]`, и программа выводит **`42`**.
