```cpp
int x=10, y=3;
```

```cpp
int x=10, y=9;

```

#### Решение

##### Фрагмент 1

```cpp
int x=10, y=3;
std::cout << std::min(x=15, x+y);
```

Файл: [01/frag1.cpp](01/frag1.cpp).

**Поведение:** данный фрагмент обладает **неоднозначным поведением** (unspecified order of evaluation, а до стандарта C++17 — **неопределенным поведением**, Undefined Behavior).

**Причина:**

1. Функция `std::min` принимает два аргумента: первый аргумент — выражение присваивания `x=15`, второй аргумент — выражение `x+y`.
2. По правилам языка C++ порядок вычисления аргументов функции **не зафиксирован стандартом** (unspecified behavior). Компилятор имеет право вычислить первым либо `x=15`, либо `x+y`.
3. До стандарта C++17 вычисления аргументов функции были не упорядочены относительно друг друга (unsequenced). По стандарту ([intro.execution]), если в одном выражении происходит модификация скалярного объекта (`x=15`) и чтение того же объекта (`x+y`) без упорядочивания точками следования (sequencing), поведение программы является **неопределенным (UB)**.
4. Начиная с C++17, вычисления аргументов функции стали *indeterminately sequenced* (вычисления не чередуются по инструкциям, одно гарантированно завершается до начала другого), однако порядок между ними всё равно остаётся не специфицированным:
   - Если первым вычисляется `x=15`: переменная `x` становится равной 15. Затем вычисляется второй аргумент `x+y = 15 + 3 = 18`. Вызов `std::min(15, 18)` возвращает **15**.
   - Если первым вычисляется `x+y`: вычисляется `10 + 3 = 13`. Затем вычисляется `x=15`. Вызов `std::min(15, 13)` возвращает **13**.

**Проверка компиляторами:**

При компиляции с флагами `-Wall -Wextra` оба компилятора предупреждают о проблеме с последовательностью вычислений:
* `g++ 14.2`:
  ```
  frag1.cpp:5:27: warning: operation on 'x' may be undefined [-Wsequence-point]
      5 |    std::cout << std::min(x=15, x+y);
  ```
* `clang++ 19.1`:
  ```
  frag1.cpp:5:27: warning: unsequenced modification and access to 'x' [-Wunsequenced]
      5 |    std::cout << std::min(x=15, x+y);
  ```

Результаты запуска скомпилированных программ:
* `g++` (C++14 и C++17): вывел **`13`** (вычислил `x+y` первым);
* `clang++` (C++17): вывел **`15`** (вычислил `x=15` первым).

Разные компиляторы выдали разные ответы для одной и той же программы.

##### Фрагмент 2

```cpp
int x=10, y=3;
x=15, y+=x, x+=y;
```

Файл: [01/frag2.cpp](01/frag2.cpp).

**Поведение:** данный фрагмент обладает **строго определённым (однозначным)** поведением.

**Причина:**

В выражении используется **встроенный оператор «запятая»** (`comma operator`, `,`).
По стандарту C++ ([expr.comma]):
1. Оператор «запятая» имеет наименьший приоритет среди всех операторов языка и левую ассоциативность.
2. Оператор «запятая» гарантирует строгий порядок вычисления слева направо: вычисление левого операнда и все его побочные эффекты строго предшествуют (*sequenced before*) вычислению правого операнда. Результат левого выражения отбрасывается.

Пошаговое выполнение:
1. `x = 15`: переменной `x` присваивается значение 15. Значение выражения (15) отбрасывается.
2. `y += x`: вычисляется `y = 3 + 15 = 18`. Переменная `y` получает значение 18.
3. `x += y`: вычисляется `x = 15 + 18 = 33`. Переменная `x` получает значение 33.

Никакой неоднозначности нет. Программа гарантированно и одинаково на всех компиляторах дает результат:
```
x=33 y=18
```

##### Фрагмент 3

```cpp
int x=10, y=9;
if (x>y++ && y++>9)
  cout << "yes" << endl;
cout << y;
```

Файл: [01/frag3.cpp](01/frag3.cpp).

**Поведение:** данный фрагмент обладает **строго определённым (однозначным)** поведением.

**Причина:**

В условии используется **логический оператор «И»** (`&&`).
По стандарту C++ ([expr.log.and]):
1. Оператор `&&` вычисляется строго слева направо.
2. Вычисление левого операнда и все его побочные эффекты строго предшествуют (*sequenced before*) вычислению правого операнда.
3. Оператор `&&` реализует «короткое замыкание» (short-circuit evaluation): правый операнд вычисляется только в том случае, если левый операнд истинен (`true`).

Пошаговое выполнение:
1. Вычисляется левый операнд `x > y++`:
   - Текущие значения: `x = 10`, `y = 9`.
   - Постфиксный инкремент `y++` возвращает старое значение `9`.
   - Проверяется условие: `10 > 9` — истинно (`true`).
   - Побочный эффект постфиксного инкремента выполняется: `y` увеличивается до `10`.
2. Так как левый операнд истинен, управление переходит к вычислению правого операнда `y++ > 9`:
   - На входе `y = 10`.
   - Постфиксный инкремент `y++` возвращает старое значение `10`.
   - Проверяется условие: `10 > 9` — истинно (`true`).
   - Побочный эффект второго постфиксного инкремента выполняется: `y` увеличивается до `11`.
3. Так как оба операнда истинны, условие `if` выполняется. В поток выводится строка `"yes\n"`.
4. Следующая строка `cout << y;` выводит текущее значение `y`, то есть `11`.

Вывод программы:
```
yes
11
```
Поведение однозначно, предупреждений компилятора нет.

### Задание 2 **(2)**
*Как записать следующие строки программы на С++ в виде одного выражения? Приведите несколько способов, в том числе с использованием операторов инкремента.*
*Проверьте работу написанных программ*
```cpp
x=x+1;
z=z+2*x+3*y;
y=y+1;
```
*Тексты программ разместите в папке с номером задания*

#### Решение

Файл с реализацией и проверкой всех способов: [02/main.cpp](02/main.cpp).

Исходные строки:
```cpp
x=x+1;
z=z+2*x+3*y;
y=y+1;
```

При исходных значениях `x=2, y=3, z=0`:
* `x` увеличивается на 1: $x = 3$;
* `z` вычисляется с новым $x$ и старым $y$: $z = 0 + 2 \cdot 3 + 3 \cdot 3 = 15$;
* `y` увеличивается на 1: $y = 4$.
Итоговые значения: `x=3, y=4, z=15`.

##### Способы записи в виде одного выражения

**Способ 1: использование оператора «запятая»**
```cpp
x=x+1, z=z+2*x+3*y, y=y+1;
```
Оператор «запятая» разделяет три подвыражения внутри одной инструкции. Они гарантированно вычисляются строго слева направо: сначала инкрементируется `x`, затем вычисляется `z`, затем инкрементируется `y`.

**Способ 2: использование префиксного инкремента и запятой**
```cpp
z += 2*(++x) + 3*y, ++y;
```
Префиксный инкремент `++x` сначала увеличивает `x` на 1, после чего его новое значение сразу участвует в вычислении `2*(++x)`. Переменная `y` в выражении для `z` берется еще до инкремента. Затем через оператор запятая выполняется `++y`.

**Способ 3: префиксные инкременты с оператором запятая**
```cpp
++x, z += 2*x + 3*y, ++y;
```
В первом подвыражении префиксно увеличивается `x`, во втором вычисляется обновленный `z`, в третьем префиксно увеличивается `y`.

**Способ 4: одно выражение без оператора «запятая» (смешанные инкременты)**
```cpp
z += 2*(++x) + 3*y++;
```
В этом выражении объединены все три операции в одну:
1. `++x` префиксно увеличивает `x` на 1 и возвращает его новое значение, которое умножается на 2.
2. `y++` постфиксно возвращает старое значение `y`, которое умножается на 3, а затем увеличивает `y` на 1.
3. Результат суммируется и прибавляется к `z`.

Поскольку выражения модифицируют **три разные переменные** (`x`, `y`, `z`), здесь нет одновременной модификации одного и того же объекта, и неопределенное поведение отсутствует. Компиляторы `g++` и `clang++` компилируют данное выражение без каких-либо предупреждений даже с `-Wall -Wextra`.

##### Результат работы программы [02/main.cpp](02/main.cpp)
```
Original: x=3 y=4 z=15
Method 1 (comma): x=3 y=4 z=15
Method 2 (prefix ++x): x=3 y=4 z=15
Method 3 (prefix both): x=3 y=4 z=15
Method 4 (mixed): x=3 y=4 z=15
```
Все способы дают идентичный корректный результат.

### Задание 4 **(2)**

*Почему присваивание* ```(++x)=y``` *является синтаксически правильным, а*
```(x++)=y``` - *нет? Запишите текст сообщения об ошибке, переведите и объясните его.*

#### Решение

Файлы с кодом: [04/prefix.cpp](04/prefix.cpp) и [04/postfix.cpp](04/postfix.cpp).

##### Сообщения об ошибке компиляторов

При попытке скомпилировать `(x++) = y;` в файле [04/postfix.cpp](04/postfix.cpp):

* **g++ (GCC 14.2):**
  ```
  postfix.cpp:4:7: error: lvalue required as left operand of assignment
      4 |     (x++) = y;
        |     ~~^~~
  ```
  *Перевод:* «В качестве левого операнда присваивания требуется lvalue (адресуемое значение)».

* **clang++ (Clang 19.1):**
  ```
  postfix.cpp:4:11: error: expression is not assignable
      4 |     (x++) = y;
        |     ~~~~~ ^
  ```
  *Перевод:* «Выражение не является доступным для присваивания (выражению нельзя присвоить значение)».

В то же время файл [04/prefix.cpp](04/prefix.cpp) с выражением `(++x) = y;` компилируется без ошибок и выводит `x=10`.

##### Объяснение причины

Различие заключается в категории значений (**value category**), которые возвращают операторы префиксного и постфиксного инкремента в C++ ([cppreference: Value categories](https://en.cppreference.com/w/cpp/language/value_category)):

| Оператор | Сигнатура / тип возвращаемого значения | Категория значения | Является ли целью присваивания? |
|---|---|---|---|
| Префиксный `++x` | `T& operator++()` | **lvalue** (ссылка на существующий объект) | **Да** |
| Постфиксный `x++` | `T operator++(int)` | **prvalue** (временное безымянное значение) | **Нет** |

1. **Префиксный инкремент `++x`:**
   Увеличивает значение переменной `x` в памяти и возвращает **ссылку на саму переменную `x`** (`int&`). Это выражение является **lvalue** — оно указывает на конкретную ячейку памяти, идентифицирующую объект. В C++ оператор присваивания требует, чтобы левый операнд был модифицируемым lvalue. Поэтому выражение `(++x) = y` синтаксически корректно: переменная `x` сначала увеличивается, а затем в эту же переменную записывается значение `y`.

2. **Постфиксный инкремент `x++`:**
   Сохраняет текущее значение `x` во временном безымянном значении, увеличивает переменную `x`, а затем возвращает это **старое значение по значению** (`int`). Результат выражения — **prvalue (pure rvalue)**, то есть временная константа-значение, не привязанная к сохраняемому объекту памяти. По правилам C++ временному значению (rvalue) нельзя ничего присвоить (это эквивалентно бессмысленной записи `5 = y;`). Поэтому компилятор отклоняет строку `(x++) = y;` на этапе синтаксического анализа.

*(Примечание: в языке Си префиксный инкремент `++x` также возвращает rvalue, поэтому в Си не скомпилировались бы оба варианта. В C++ префиксный инкремент был специально переопределен для возврата lvalue-ссылки).*

### Задание 5 **(2)**

*Программисты на Python для обмена значений двух переменных часто пишут строку*
```python
a,b = b,a
```
*Проверьте, будет ли аналогичная строка на С++ (с точкой с запятой в конце) являться синтаксически
правильной? Будет ли она обменивать значения переменных? Как в языке С++ вычисляется это выражение?*

#### Решение

Файлы с кодом: [05/main.cpp](05/main.cpp) и [05/explain.cpp](05/explain.cpp).

##### Ответы на вопросы

1. **Является ли строка `a,b = b,a;` синтаксически правильной в C++?**
   **Да**, эта строка является синтаксически правильной и успешно проходит компиляцию.
2. **Будет ли она обменивать значения переменных?**
   **Нет**, значения переменных не обмениваются и остаются прежними.
3. **Как в языке С++ вычисляется это выражение?**
   Выражение разбирается компилятором через приоритеты операторов как последовательность из трёх выражений, разделённых оператором «запятая»: `(a), (b = b), (a);`.

##### Подробный разбор вычисления

В языке C++:
* Оператор присваивания `=` имеет приоритет 16.
* Оператор «запятая» `,` имеет приоритет 17 (наименьший приоритет в языке).

Из-за приоритета оператор `=` связывает операнды теснее, чем запятая. Поэтому компилятор разбирает строку:
```cpp
a,b = b,a;
```
не как параллельное присваивание, а следующим образом:
```cpp
(a) , (b = b) , (a);
```

Оператор запятая вычисляет операнды строго слева направо и отбрасывает результаты всех операндов, кроме последнего:
1. Вычисляется левый операнд `a`: его значение читается и отбрасывается.
2. Вычисляется центральный операнд `b = b`: переменной `b` присваивается её собственное значение (**самоприсваивание**), значение `b` не меняется.
3. Вычисляется правый операнд `a`: его значение читается и отбрасывается.

В результате переменная `a` вообще не модифицируется, а переменная `b` присваивается сама себе. Исходные значения сохраняются.

##### Предупреждения компилятора

При сборке файла [05/main.cpp](05/main.cpp) компиляторы подтверждают этот разбор:
* `g++`:
  ```
  main.cpp:5:5: warning: left operand of comma operator has no effect [-Wunused-value]
  main.cpp:5:14: warning: right operand of comma operator has no effect [-Wunused-value]
  ```
* `clang++`:
  ```
  main.cpp:5:9: warning: explicitly assigning value of variable of type 'int' to itself [-Wself-assign]
  main.cpp:5:5: warning: left operand of comma operator has no effect [-Wunused-value]
  main.cpp:5:13: warning: expression result unused [-Wunused-value]
  ```

##### Вывод программы
```
Before: a=1 b=2
After:  a=1 b=2
```

##### Почему это работает в Python и как делать в C++
* В Python запятая используется для конструирования кортежей: `b, a` создаёт кортеж `(b, a)`, а конструкция `a, b = ...` распаковывает его в переменные.
* В C++ для обмена значений двух переменных используется стандартная библиотечная функция `std::swap(a, b);` из заголовочного файла `<utility>` (или `<algorithm>`), либо временная переменная.

##### Экспериментальные данные

Замеры времени выполнения на одной и той же машине (процессор с оптимизацией `-O2`):

| Число итераций $N$ | `s += 'a'` (fast) | `s = s + 'a'` (slow) | Во сколько раз медленнее |
|---|---|---|---|
| $10\,000$ | **0.048 мс** (48 мкс) | **4 мс** | $\approx 83$ раза |
| $20\,000$ | **0.080 мс** (80 мкс) | **12 мс** | $\approx 150$ раз |
| $50\,000$ | **0.240 мс** (240 мкс) | **200 мс** | $\approx 830$ раз |
| $100\,000$ | **0.375 мс** (375 мкс) | **742 мс** | $\approx 2000$ раз |
| $1\,000\,000$ | **4.3 мс** | **$\approx 74$ секунды** (экстраполяция: $74\,200$ мс) | **$\approx 17\,000$ раз** |

При замене третьей строки время выполнения катастрофически увеличивается — программа с $1\,000\,000$ итераций вместо долей секунды выполняется больше минуты.

##### Объяснение результата

Разница объясняется алгоритмической сложностью и механизмом выделения памяти в `std::string`:

```
                      +-------------------+--------------------+
                      |     s += 'a';     |    s = s + 'a';    |
+---------------------+-------------------+--------------------+
| Сложность 1 шага    | Амортизир. O(1)   | O(i) (длина строки)|
| Общая сложность     | Линейная O(N)     | Квадратичная O(N²) |
| Число аллокаций     | ~25 за 10⁶ шагов  | 1 000 000          |
| Объем копирований   | ~2 МБ             | ~500 ГБайт!        |
+---------------------+-------------------+--------------------+
```

###### 1. Как работает `s += 'a'`
Класс `std::string` использует концепцию **емкости (capacity)**. Буфер строки выделяется «с запасом».
Когда текущей емкости перестает хватать, строка выделяет новый буфер в 1.5–2 раза больше предыдущего (геометрическая прогрессия).
За миллион добавлений перевыделение памяти и копирование происходит всего $\approx \log_2(1\,000\,000) \approx 20\text{–}25$ раз. Все остальные добавления символа заключаются в записи одного байта по указателю и инкременте счетчика длины — это операция с **амортизированной сложностью $O(1)$**.
Общая сложность алгоритма — **$O(N)$** (линейная). Для миллиона символов требуется менее 5 миллисекунд.

###### 2. Как работает `s = s + 'a'`
Оператор конкатенации `+` не модифицирует строку `s` на месте. Вместо этого:
1. Создается **новый временный объект** `std::string`.
2. В куче аллоцируется память под размер $i + 1$.
3. В новый буфер **целиком копируются** все накопленные $i$ символов строки `s`.
4. В конец дописывается символ `'a'`.
5. Результат перемещается/копируется в `s`, а старый буфер освобождается.

На $i$-й итерации копируется $i$ символов. Суммарный объем скопированных данных за $N = 1\,000\,000$ итераций составляет сумму арифметической прогрессии:
$$\sum_{i=0}^{N-1} i = \frac{(N - 1) \cdot N}{2} \approx \frac{10^6 \cdot 10^6}{2} = 5 \cdot 10^{11} \text{ байт} \approx 500 \text{ гигабайт!}$$

Программа вынуждена совершить 1 миллион обращений к системному менеджеру памяти (`malloc`/`free`) и скопировать 500 гигабайт данных в памяти. Поэтому сложность составляет **$O(N^2)$**, что приводит к замедлению в десятки тысяч раз.

### Задание 7 **(2)**

*Как работает следующая программа? Как зависит результат от исходного значения?*
```cpp
int x;
std::cin >> x;
x-->0 && x-->0 && x-->0 && x-->0 && x-->0;
std::cout << x;
```

#### Решение

Файл с кодом: [07/main.cpp](07/main.cpp).

Код программы:
```cpp
int x;
std::cin >> x;
x-->0 && x-->0 && x-->0 && x-->0 && x-->0;
std::cout << x;
```

##### Разбор синтаксиса и принципа работы

1. Выражение `x-->0` согласно правилу «наибольшего куска» (maximal munch) разбирается компилятором как:
   ```cpp
   (x--) > 0
   ```
   Здесь используются два оператора:
   - `x--`: постфиксный декремент (возвращает текущее значение `x`, после чего уменьшает `x` на 1);
   - `> 0`: проверка, было ли значение до декремента строго больше нуля.
2. В строке записана цепочка из 5 таких условий, объединенных оператором **логического «И» (`&&`)**.
3. Оператор `&&` обладает свойством **короткого замыкания (short-circuit evaluation)**: вычисление выражений идет строго слева направо и **немедленно прекращается**, как только очередное условие оказывается ложным (`false`). Оставшиеся условия справа даже не вычисляются, и соответствующие декременты `x` не происходят!

##### Зависимость результата от исходного значения

Рассмотрим три характерных диапазона исходного значения $x$:

###### 1. Исходное $x < 0$ (отрицательные числа)
Первое же условие `(x--) > 0` дает `false` (так как отрицательное число не больше 0).
Выполняется ровно один декремент, после чего вычисление прерывается по короткому замыканию.
Результат: $x_{исх} - 1$.
* При $x = -5 \implies -6$;
* При $x = -1 \implies -2$.

###### 2. Исходное $0 \le x \le 4$ (числа от нуля до четырех)
Условия вычисляются по очереди, уменьшая `x` на каждом шаге на 1.
Вычисление остановится ровно тогда, когда значение `x` до декремента станет равным `0`. В этот момент проверка `0 > 0` вернет `false`, произойдет декремент $0 - 1 = -1$, и вычисление оставшихся условий прервется.
Поэтому для любого $x \in \{0, 1, 2, 3, 4\}$ результат **всегда равен `-1`**:
* $x = 0$: 1-я проверка: `0 > 0` (false) $\to x$ становится **`-1`**, стоп.
* $x = 1$: 1-я: `1 > 0` (true, $x \to 0$); 2-я: `0 > 0` (false, $x \to -1$), стоп. Результат: **`-1`**.
* $x = 2$: две проверки true, 3-я проверка: `0 > 0` (false, $x \to -1$), стоп. Результат: **`-1`**.
* $x = 3$: три проверки true, 4-я проверка: `0 > 0` (false, $x \to -1$), стоп. Результат: **`-1`**.
* $x = 4$: четыре проверки true, 5-я проверка: `0 > 0` (false, $x \to -1$). Результат: **`-1`**.

###### 3. Исходное $x \ge 5$ (числа пять и более)
Все 5 условий оказываются истинными (`true`), так как на всех пяти проверках значение `x` остается $> 0$.
Срабатывают все 5 декрементов.
Результат: $x_{исх} - 5$.
* При $x = 5 \implies 5 - 5 = 0$;
* При $x = 6 \implies 6 - 5 = 1$;
* При $x = 10 \implies 10 - 5 = 5$.

##### Сводная таблица результатов

| Исходное значение $x$ | Сколько проверок выполнено | Конечное значение $x$ |
|---|---|---|
| $x < 0$ | 1 | $x - 1$ |
| $x = 0$ | 1 | **-1** |
| $x = 1$ | 2 | **-1** |
| $x = 2$ | 3 | **-1** |
| $x = 3$ | 4 | **-1** |
| $x = 4$ | 5 | **-1** |
| $x \ge 5$ | 5 | $x - 5$ |

Математическая формула зависимости:
$$f(x) = \begin{cases} x - 1, & x < 0 \\ -1, & 0 \le x \le 4 \\ x - 5, & x \ge 5 \end{cases}$$

##### Анализ конструкций программы

1. **Тело цикла: `(s += i) += j;`**
   Оператор `s += i` изменяет значение `s` на `s + i` и возвращает lvalue-ссылку на `s`. К этой ссылке затем применяется `+= j`. Таким образом, на каждой итерации к переменной `s` просто прибавляется величина `i + j`:
   $$s_{новое} = s_{старое} + (i + j)$$
2. **Шаг цикла: `(i < j ? i : j)++`**
   Тернарный условный оператор `?:` в C++, когда оба операнда `i` и `j` являются lvalue одного типа, возвращает **lvalue-ссылку** на выбранную переменную.
   К возвращенной ссылке применяется постфиксный инкремент `++`:
   - Если `i < j`, инкрементируется переменная `i`;
   - Если `i >= j` (в частности, при равенстве `i == j`), инкрементируется переменная `j`.
3. **Условие продолжения цикла:** `i + j <= 16`.

### Задание 9 **(3)**
*Рассмотрите следующую программу. Предполагается, что на вход подается некоторый
индекс в массиве - число от нуля до девяти и значение, которое надо записать по этому индексу.*
```cpp
int i = 0;
std::vector<int> x(10);
std::cin >> i >> x[i];

```
*Проверьте работу этой программы на различных компиляторах. Найдите два компилятора (можно 
проверить онлайн компиляторы), на которых эта программа будет давать различные ответы при одинаковом
вводе. Как это объяснить?*

#### Решение

Файл с программой: [09/main.cpp](09/main.cpp).

Код программы:
```cpp
int i = 0;
std::vector<int> x(10);
std::cin >> i >> x[i];
std::cout << x[i];
```

##### Сравнение результатов на различных компиляторах

Подадим на вход индекс `3` и значение `42` (ввод: `3 42`):

| Компилятор | Стандарт языка | Результат вывода | Записанное значение |
|---|---|---|---|
| **GCC 14.2 / Clang 19.1** | C++11, C++14, C++17, C++20 | **`42`** | `x[3] = 42` |
| **MSVC (Visual Studio 2019/2022)** | **`/std:c++14`** | **`0`** | `x[0] = 42`, а `x[3] = 0` |
| **MSVC (Visual Studio 2019/2022)** | **`/std:c++17`** | **`42`** | `x[3] = 42` |

При абсолютно одинаковом коде и входных данных компиляторы **GCC/Clang** и **MSVC в режиме C++14** выводят совершенно разные ответы: `42` и `0`!

##### Объяснение причин различия

Строка ввода:
```cpp
std::cin >> i >> x[i];
```
В языке C++ оператор `>>` левоассоциативен и для потоков является вызовом перегруженной функции `operator>>`. Данное выражение эквивалентно следующему вложенному вызову функций:
```cpp
operator>>( operator>>(std::cin, i) , x[i] )
```
Здесь внешний вызов `operator>>` принимает два аргумента:
1. Первый аргумент (левый): результат `cin >> i` (поток ввода после считывания `i`);
2. Второй аргумент (правый): ссылка на элемент вектора `x[i]`.

###### До стандарта C++17 (поведение MSVC `/std:c++14`)
По стандарту C++14 порядок вычисления аргументов функции **не был специфицирован** ([intro.execution]). Компилятор имел право вычислять аргументы функции в любом порядке.

Компилятор MSVC при генерации кода традиционно использует порядок вычисления аргументов функции **справа налево**:
1. Сначала вычисляется правый аргумент `x[i]`. Поскольку переменная `i` была инициализирована нулем (`int i = 0`), вычисляется адрес элемента **`x[0]`**! Этот адрес сохраняется во временный регистр/стек.
2. Затем вычисляется левый аргумент `operator>>(cin, i)`: из входного потока считывается число `3` и записывается в переменную `i`. Переменная `i` становится равной 3.
3. Затем вызывается внешний `operator>>`, который считывает число `42` по ранее вычисленному адресу — то есть в **`x[0]`**!
4. В следующей строке `std::cout << x[i];` берется текущее значение `i` (равное 3) и выводится элемент `x[3]`. Но в `x[3]` ничего не записывалось — вектор был создан с нулями, поэтому программа выводит **`0`**! А число 42 осталось лежать в `x[0]`.

Ассемблерный код, сгенерированный MSVC в режиме C++14 (Godbolt Compiler Explorer):
```asm
movsxd  rax, DWORD PTR i$[rsp]
lea     rcx, QWORD PTR x$[rsp]
call    vector::operator[]
mov     QWORD PTR tv77[rsp], rax

lea     rdx, QWORD PTR i$[rsp]
mov     rcx, std::cin
call    istream::operator>>

mov     rdx, QWORD PTR tv77[rsp]
mov     rcx, rax
call    istream::operator>>
```

###### Начиная со стандарта C++17 (поведение C++17 и GCC/Clang)
В стандарте C++17 был принят документ **P0145R3** (*«Refining Expression Evaluation Order for Idiomatic C++»*), который исправил этот дефект языка.
В C++17 пункт стандарта [expr.shift] явно зафиксировал:
> В выражении `E1 >> E2` вычисление выражения `E1` и все связанные с ним побочные эффекты строго предшествуют (*sequenced before*) вычислению выражения `E2`.

При перегрузке операторов с инфиксной формой записи правило сохранения порядка операндов C++17 распространяется и на вызовы функций перегруженных операторов.

Поэтому в стандарте C++17 (и в GCC/Clang во всех режимах):
1. Выражение `std::cin >> i` строго обязано вычислиться **до** вычисления `x[i]`.
2. Сначала считывается новое значение `i = 3`.
3. Затем с новым значением индекса вычисляется `x[3]`.
4. Значение `42` записывается в `x[3]`.
5. `std::cout << x[i]` выводит **`42`**.
